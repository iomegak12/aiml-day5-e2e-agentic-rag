Call Forwarding, Hunt Groups and Voicemail Setup

KB-MTG-2005 | NetCore Calling 5.0 | Last updated: 2026-08-01 | Status: current

Summary

This article describes how to configure NetCore Calling 5.0 call forwarding, hunt groups, and voicemail in NetCore Control Hub, with equivalent CLI examples for repeatable administration. It also covers user self-service options and verification steps, including how to identify MTG-CALL-7002 Number Not Provisioned conditions.

Applies to: NetCore Calling 5.0, NetCore Control Hub, NetCore Calling users, hunt groups, voicemail, Meet Business and Meet Enterprise organizations using NetCore Calling

Overview

NetCore Calling 5.0 supports user-level call forwarding, location-based hunt groups, and voicemail with greeting, PIN, and e-mail delivery settings. Administrators configure these services in NetCore Control Hub, while end users can manage selected personal settings from the NetCore Calling user portal or the NetCore Meet desktop and mobile apps.

Call forwarding supports three modes: always, busy, and no-answer. The no-answer forwarding timer is fixed at 20 seconds in release 5.0. Hunt groups support circular, top-down, and simultaneous routing. Voicemail can be enabled per user with a recorded or uploaded greeting, numeric PIN, and optional e-mail delivery of voicemail notifications.

All users and hunt groups that receive inbound calls must have provisioned E.164 numbers. If a number is assigned in forwarding, hunt group, or voicemail routing before it is provisioned, NetCore Calling may raise MTG-CALL-7002 Number Not Provisioned. For number inventory and location dial plan setup, see KB-MTG-2002.

Prerequisites

Complete the following prerequisites before configuring call forwarding, hunt groups, or voicemail. These checks prevent failed routing and MTG-CALL-7002 Number Not Provisioned alarms.

  • Confirm the tenant is running NetCore Calling 5.0.
  • Confirm each user has an active NetCore Calling licence and an assigned E.164 number, for example +15551201001.
  • Confirm each shared service number, such as a hunt group pilot number, is provisioned in the correct location.
  • Confirm the location dial plan is already configured. Outbound prefix 9 is optional and does not change the E.164 format required for forwarding destinations. See KB-MTG-2002.
  • Confirm administrators have the Calling Administrator or Organization Administrator role in NetCore Control Hub.
  • Confirm voicemail e-mail delivery is permitted by the organization messaging policy if voicemail messages or notifications will be sent by e-mail.
ncctl login --tenant acme-prod --role calling-admin
ncctl calling tenant show --fields release,callingStatus
ncctl calling numbers show --location NYC --status provisioned
ncctl calling users show --location NYC --licensed true

Step-by-step Procedure

Use the following procedure to configure forwarding, hunt groups, voicemail, and user self-service policy. The NetCore Control Hub path is shown first, followed by an equivalent CLI example for administrators who maintain changes as code.

In NetCore Control Hub, open Calling > Users to configure user forwarding and voicemail. Open Calling > Hunt Groups to create and manage hunt groups. Open Calling > Policies > User Self-Service to control which settings users can modify themselves.

  • 1. Validate number provisioning. In Control Hub, go to Calling > Numbers and verify that all user, forwarding destination, and hunt group pilot numbers are listed as Provisioned. If a number is missing, provision it first as described in KB-MTG-2002.
  • 2. Configure call forwarding for a user. In Control Hub, go to Calling > Users > select the user > Call handling > Forwarding. Enable Always, Busy, or No-answer forwarding, then enter the destination in E.164 format. For no-answer forwarding, NetCore Calling uses the fixed 20-second timer.
  • 3. Create a hunt group. In Control Hub, go to Calling > Hunt Groups > Create Hunt Group. Select the location, assign a provisioned E.164 pilot number, choose circular, top-down, or simultaneous routing, and add members in the required order.
  • 4. Configure voicemail. In Control Hub, go to Calling > Users > select the user > Voicemail. Enable voicemail, upload or record the greeting, set or reset the numeric PIN, and enable e-mail notification or delivery if permitted by policy.
  • 5. Configure user self-service. In Control Hub, go to Calling > Policies > User Self-Service. Allow or deny users the ability to manage their own call forwarding, voicemail greeting, voicemail PIN, and voicemail e-mail delivery settings.
  • 6. Save changes and allow up to two minutes for the calling configuration to propagate across the tenant.

Verification

Verify the configuration from both the administrative plane and the call-routing plane. The examples below show successful configuration and a common failure caused by referencing an unprovisioned number.

If the CLI or Control Hub displays MTG-CALL-7002 Number Not Provisioned, check the referenced E.164 number in Calling > Numbers and confirm it is provisioned in the correct location. Correct the number assignment or provision the number as described in KB-MTG-2002.

  • Verify the user forwarding profile shows the expected forwarding modes and destinations.
  • Verify the hunt group pilot number, routing mode, and member order.
  • Place test calls to the user number and each hunt group pilot number.
  • For voicemail, allow a call to go unanswered, confirm the greeting plays, leave a message, and verify the message appears in the user mailbox or e-mail delivery target.
  • Check the calling event log for rejected routing updates or MTG-CALL-7002 Number Not Provisioned alarms.

Rollback

Rollback should restore the previous routing behavior without deleting number inventory. Disable forwarding rules, remove or deactivate hunt groups, and reset voicemail settings only for the affected users.

If a rollback is required because of MTG-CALL-7002 Number Not Provisioned, remove the unprovisioned destination from forwarding or hunt group configuration first, then reapply the last known-good configuration.

  • Disable user forwarding rules or restore the previous destination.
  • Deactivate the hunt group before deleting it if active calls may still be present.
  • Remove members from the hunt group only after confirming no inbound calls are being routed to the pilot number.
  • Disable voicemail e-mail delivery or restore the previous e-mail destination.
  • Ask users to confirm their self-service settings after rollback if user-level changes were allowed.
# Disable forwarding for a user
ncctl calling user forwarding update alex.rivera@example.internal \
  --always disabled \
  --busy disabled \
  --no-answer disabled

# Deactivate a hunt group but keep the pilot number reserved
ncctl calling hunt-group update hg-nyc-support --status inactive

# Optional: delete the hunt group after validation
ncctl calling hunt-group delete hg-nyc-support --confirm

# Disable voicemail e-mail delivery while keeping voicemail enabled
ncctl calling voicemail update alex.rivera@example.internal \
  --enabled true \
  --email-delivery disabled

# Restore user self-service policy to a restricted state
ncctl calling policy self-service update \
  --allow-forwarding-changes false \
  --allow-voicemail-greeting-changes true \
  --allow-voicemail-pin-changes true \
  --allow-voicemail-email-delivery-changes false

Known Limitations

NetCore Calling 5.0 has the following limitations for call forwarding, hunt groups, and voicemail configuration.

  • No-answer forwarding uses a fixed 20-second timer. The timer is not configurable in release 5.0.
  • Forwarding destinations, hunt group pilot numbers, and user numbers must be provisioned E.164 numbers. Unprovisioned numbers can trigger MTG-CALL-7002 Number Not Provisioned.
  • Supported hunt group routing modes are circular, top-down, and simultaneous only.
  • User self-service can allow personal forwarding and voicemail changes, but standard users cannot create or delete hunt groups.
  • The optional outbound prefix 9 is used for dialing behavior only; it does not replace E.164 number provisioning requirements.
  • Voicemail e-mail delivery depends on the organization messaging policy. If e-mail delivery is disabled by policy, users may still access voicemail from the NetCore Calling interface.

NCS Alarm and Error Code Reference

KB-NET-1008 | NetCore SD-WAN 5.0 | Last updated: 2026-09-30 | Status: current

Summary

This reference lists the NetCore SD-WAN 5.0 NCS alarm and error codes used by NetCore Orchestrator and NCX edge devices. It includes the code name, severity or handling behavior, description, likely cause, recommended action, related CLI checks, and the related KB article where available.

Applies to: NetCore SD-WAN 5.0, NetCore Orchestrator, NCX-1000 branch edge, NCX-4000 regional hub, NCX-9000 data center edge

Overview

NetCore SD-WAN 5.0 raises NCS alarms from the management plane, control plane, tunnel monitoring, SLA monitoring, ZTP workflow, and QoS subsystem. The alarms in this article are the complete NCS alarm set for the current NetCore SD-WAN 5.0 release.

For SLA alarms, NetCore SD-WAN 5.0 uses an app-route poll interval of 120 seconds and a multiplier of 3. An SLA breach is declared after 3 consecutive failed intervals, approximately 6 minutes. NCS-SLA-2001 initially opens as Sev3, auto-escalates to Sev2 if the breach persists for more than 15 minutes, and escalates to Sev1 if it persists for more than 30 minutes or if 5 or more sites are affected. A ticket is automatically created in ITSM.

Release 4.2 behavior is superseded. In release 4.2, SLA polling used a 600-second interval and multiplier of 5, breach declaration took approximately 50 minutes, failover was manual, and notification was by e-mail only with no automatic severity escalation.

Quick CLI verification examples

Run the following commands from the affected NCX edge. The prompt examples use the standard NetCore SD-WAN edge prompt, ncx-edge#.

  • Use show sdwan app-route statistics to verify latency, jitter, loss, selected transport, and SLA compliance.
  • Use show sdwan bfd sessions to verify whether NCS-BFD-3004 or NCS-BFD-3005 is contributing to SLA instability.
  • Use show sdwan control connections when investigating NCS-ORC-6001, ZTP failures, or tunnel establishment issues.
  • Use show policy qos-queue counters when investigating NCS-QOS-5002 and packet loss symptoms.
  • Use request sdwan ztp restart only after correcting the cause of NCS-ZTP-4001 or NCS-ZTP-4003.

Notes on interpretation

Do not treat the code alone as the complete root cause. NCS-SLA-2001 reports that an SLA class is out of compliance; it does not by itself prove whether the root cause is congestion, loss, BFD instability, or an upstream transport issue.

For NCS-SLA-2001, release 5.0 automatic failover selects the best compliant transport. If no transport is compliant, traffic remains subject to policy behavior and the alarm continues until compliance is restored or the underlying condition is remediated.

NCS-SLA-2002 is a restoration event. Always review the preceding NCS-SLA-2001 duration and whether the alarm auto-escalated before closing the associated ITSM ticket.

NCS-BFD-3004 indicates instability, while NCS-BFD-3005 indicates the BFD session is down. A flapping tunnel can still appear Up at the moment you run show sdwan bfd sessions, so check the flap count and last-change timestamp.

NCS-ZTP-4001 and NCS-ZTP-4003 are onboarding workflow failures. Restarting ZTP without fixing redirect or certificate validation causes the same alarm to recur.

NCS-QOS-5002 should be correlated with application-route loss. Queue drops on a high-priority queue can directly affect Voice, Video, or Business-Critical SLA compliance.

NCS-ORC-6001 affects management and control visibility. If multiple sites report control connection loss at the same time, triage as a broader control-plane incident and check whether the >=5-sites Sev1 operational condition is met.

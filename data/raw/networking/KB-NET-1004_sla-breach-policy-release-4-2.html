SLA Breach Policy (Release 4.2)

KB-NET-1004 | NetCore SD-WAN 4.2 | Last updated: 2024-11-18 | Status: superseded

NOTICE: This article applies to release 4.2 and has been superseded by KB-NET-1003. It is retained for customers still running release 4.2.

Summary

This article defines the superseded NetCore SD-WAN 4.2 SLA breach policy as originally published: app-route measurements are evaluated every 600 seconds, and an SLA breach is declared only after 5 consecutive failed intervals, approximately 50 minutes. Release 4.2 uses manual failover and e-mail-only notification when NCS-SLA-2001 SLA Violation Detected is raised.

Applies to: NetCore SD-WAN 4.2, NetCore Orchestrator managing NetCore SD-WAN 4.2 edges, NCX-1000 branch edge, NCX-4000 regional hub, NCX-9000 data center edge

Purpose

This policy defines how NetCore SD-WAN 4.2 detects, reports, and responds to SLA breaches for application-aware routing. It is retained for historical reference because the policy is superseded in later releases.

The policy applies to SLA breach detection only. SLA class latency, jitter, and loss thresholds are maintained separately; see KB-NET-1002 for the SLA Class Thresholds Reference.

Scope

This policy applies to NetCore SD-WAN 4.2 deployments managed by NetCore Orchestrator and running on NCX-1000, NCX-4000, and NCX-9000 edge devices.

The policy covers detection timing, alarm generation, notification, and operational response for NCS-SLA-2001 SLA Violation Detected. It does not define traffic classification, queue behavior, or SLA class threshold values.

  • Included transports: MPLS, Internet broadband, and LTE/5G when configured as SD-WAN transports.
  • Included measurement source: app-route statistics derived from monitored tunnel path health.
  • Included response model: operator-driven review and manual failover.
  • Excluded: automatic failover, automatic severity escalation, and ITSM ticket automation.

Definitions

The following terms are used in this policy.

  • App-route poll interval: The scheduled measurement interval used by NetCore SD-WAN 4.2 to evaluate path SLA state. For this policy, the value is 600 seconds.
  • Multiplier: The number of consecutive failed app-route polling intervals required before declaring a breach. For this policy, the value is 5.
  • SLA breach: A condition where a path fails the applicable SLA class criteria for 5 consecutive 600-second polling intervals, resulting in breach declaration after approximately 50 minutes.
  • NCS-SLA-2001 SLA Violation Detected: The alarm raised by NetCore Orchestrator when the release 4.2 breach condition is met.
  • Manual failover: Operator-initiated movement of traffic to an alternate transport or path after reviewing the breach condition.

Policy Statements

NetCore SD-WAN 4.2 uses delayed breach detection to reduce false positives caused by transient transport degradation. A single failed polling interval does not create an SLA breach under this policy.

Enforcement

NetCore Orchestrator enforces the release 4.2 timing policy by evaluating app-route measurements at the configured 600-second interval and applying the multiplier of 5 before raising NCS-SLA-2001 SLA Violation Detected.

Operations teams must verify the affected SLA class and measured path health before performing manual failover. Use the edge CLI to confirm app-route statistics and the active SLA class configuration.

  • Confirm the affected application route and transport path.
  • Confirm that the breach persisted across the required 5 consecutive polling intervals.
  • Review the SLA class threshold reference in KB-NET-1002 before concluding that the measured latency, jitter, or loss is out of policy.
  • If service impact requires path movement, perform manual failover according to the approved site operating procedure.
  • Send or confirm the e-mail notification to the operations distribution list and create any required ticket manually.

Exceptions

Exceptions to this policy must be approved by the network service owner and recorded in the change record for the affected site or transport. Because release 4.2 does not provide automatic failover or automatic severity escalation, exceptions commonly involve temporary notification routing or an agreed manual response window.

An exception must not redefine the release 4.2 breach timing values. The poll interval remains 600 seconds, the multiplier remains 5, and breach declaration remains approximately 50 minutes.

  • Permitted exception: temporary change to the e-mail recipient list for NCS-SLA-2001 SLA Violation Detected.
  • Permitted exception: documented decision not to perform manual failover for a known maintenance event.
  • Not permitted: declaring a release 4.2 SLA breach after fewer than 5 consecutive failed intervals.
  • Not permitted: treating release 4.2 as having automatic severity escalation or automatic ITSM ticket creation.

SLA Breach Policy: Escalation and Auto-Failover

KB-NET-1003 | NetCore SD-WAN 5.0 | Last updated: 2026-09-04 | Status: current

Summary

This policy defines how NetCore SD-WAN 5.0 detects SLA breaches, declares and clears alarms, performs automatic transport failover, and escalates incident severity. It applies to SLA monitoring performed by NetCore Orchestrator and NCX edge devices using BFD-monitored SD-WAN tunnels.

Applies to: NetCore SD-WAN 5.0, NetCore Orchestrator, NCX-1000 branch edge, NCX-4000 regional hub, NCX-9000 data center edge, MPLS, Internet broadband, and LTE/5G transports

Purpose

The purpose of this policy is to standardize SLA breach handling for NetCore SD-WAN 5.0 across all managed sites. The policy covers breach detection timing, automatic failover behavior, severity escalation, ticket creation, notification channels, exceptions, and restoration handling.

For SLA class threshold values by application class, see KB-NET-1002. For alarm-level troubleshooting of NCS-SLA-2001 SLA Violation Detected, see KB-NET-1005. For the superseded NetCore SD-WAN 4.2 policy, see KB-NET-1004.

Scope

This policy applies to NetCore SD-WAN 5.0 deployments managed by NetCore Orchestrator, including NCX-1000, NCX-4000, and NCX-9000 edge devices. It applies to app-route SLA monitoring over MPLS, Internet broadband, and LTE/5G transports where tunnels are monitored with BFD probes.

This policy governs the SLA alarm lifecycle for NCS-SLA-2001 SLA Violation Detected and NCS-SLA-2002 SLA Restored. The following alarm codes may be related during investigation but are not governed by this SLA breach policy: NCS-BFD-3004 BFD Session Flap, NCS-BFD-3005 BFD Session Down, NCS-ZTP-4001 ZTP Redirect Failed, NCS-ZTP-4003 Device Certificate Validation Failed, NCS-QOS-5002 Queue Drop Threshold Exceeded, and NCS-ORC-6001 Orchestrator Control Connection Lost.

  • In scope: SLA breach detection, automatic failover, severity assignment, severity escalation, ITSM ticketing, and notifications for NetCore SD-WAN 5.0.
  • Out of scope: provisioning failures, ZTP certificate failures, QoS queue-drop remediation, BFD session recovery procedures, and Orchestrator control-plane outage recovery.
  • Release note: NetCore SD-WAN 4.2 used a different breach policy with a 600-second poll interval, multiplier 5, manual failover only, e-mail notification only, and no automatic severity escalation. See KB-NET-1004.

Definitions

The following terms are used consistently in this policy.

  • SLA class: A policy class such as Voice, Video, Business-Critical, or Best-Effort with latency, jitter, and loss thresholds. Refer to KB-NET-1002 for the full threshold reference.
  • App-route poll interval: The interval at which NetCore SD-WAN evaluates path health for application routing. In release 5.0, the interval is 120 seconds.
  • Multiplier: The number of consecutive failed app-route polling intervals required before a breach is declared. In release 5.0, the multiplier is 3.
  • SLA breach: A condition where measured latency, jitter, or packet loss exceeds the configured SLA class threshold for 3 consecutive 120-second intervals, approximately 6 minutes.
  • Compliant transport: A transport path currently meeting the SLA class thresholds for the affected application traffic.
  • Best compliant transport: The compliant transport with the best measured path quality for the affected SLA class at the time of routing decision.
  • Restoration: The condition where the affected SLA class returns within threshold and Orchestrator clears the breach state by raising NCS-SLA-2002 SLA Restored.

Policy Statements

NetCore SD-WAN 5.0 declares an SLA breach only after 3 consecutive app-route polling intervals fail for the affected SLA class. Because the poll interval is 120 seconds, the standard breach declaration time is approximately 6 minutes.

When a breach is declared, NetCore Orchestrator raises NCS-SLA-2001 SLA Violation Detected, creates an ITSM ticket automatically, assigns the initial severity according to the matrix below, and instructs affected edge devices to route the affected application class to the best compliant transport when one is available.

When the SLA condition returns to compliance, NetCore Orchestrator raises NCS-SLA-2002 SLA Restored. Restoration does not automatically erase the incident history; the ITSM ticket remains linked to the alarm record and must be closed according to the operations workflow.

  • Automatic failover is mandatory for NetCore SD-WAN 5.0 managed sites unless an approved exception is recorded under the Exceptions section.
  • Failover selection must prefer the best compliant transport among MPLS, Internet broadband, and LTE/5G based on current SLA measurements for the affected class.
  • If no compliant transport is available, traffic remains on the least-degraded available path and the incident continues to escalate according to the duration and site-impact rules.
  • Notification channels for this policy are NetCore Orchestrator alarm banner, ITSM ticket creation/update, configured operations e-mail distribution, and configured Orchestrator webhook subscriptions.
  • NCS-SLA-2001 SLA Violation Detected must not be manually suppressed to avoid escalation unless an approved maintenance window or exception exists.
  • NCS-SLA-2002 SLA Restored must be correlated to the original NCS-SLA-2001 SLA Violation Detected event for reporting and service review.

Enforcement

NetCore Orchestrator enforces this policy through app-route monitoring, BFD tunnel health inputs, alarm generation, route updates, and ITSM integration. Edge devices participate by reporting path measurements and applying the route change pushed by Orchestrator.

Network operations engineers must validate active SLA breach state from Orchestrator first, then confirm local edge telemetry if needed. The commands below are approved for validation on NCX edge devices.

  • Use show sdwan app-route statistics to verify latency, jitter, loss, selected transport, and SLA class state.
  • Use show sdwan bfd sessions to confirm whether the transport under evaluation has BFD instability that may be contributing to the SLA breach.
  • Use show sdwan sla-class to confirm the configured SLA class associated with the affected application traffic.
  • Use show sdwan control connections to verify that the edge device can receive Orchestrator policy and routing updates.
  • Use show policy qos-queue counters if packet loss appears related to local queue drops rather than WAN path impairment.
  • For procedural troubleshooting of NCS-SLA-2001 SLA Violation Detected, follow KB-NET-1005.

Exceptions

Exceptions to this policy must be approved before implementation and recorded in the site operations record. Exceptions must include the site ID, device model, affected SLA class, transport, business justification, start time, end time, approver, and rollback plan.

Exceptions do not change the NetCore SD-WAN 5.0 SLA thresholds or breach timing. They only define how operations staff respond to known or approved conditions.

  • Approved maintenance window: NCS-SLA-2001 SLA Violation Detected may be acknowledged during a planned transport maintenance window, but the alarm must remain visible in Orchestrator history.
  • Temporary transport impairment: Automatic failover remains enabled unless the exception explicitly authorizes pinning traffic to a specified transport for a limited time.
  • LTE/5G cost-control exception: Operations may restrict LTE/5G usage for selected Best-Effort traffic, but Voice, Video, and Business-Critical automatic failover must remain enabled unless explicitly approved.
  • No-compliant-transport condition: If MPLS, Internet broadband, and LTE/5G are all non-compliant, Orchestrator keeps traffic on the least-degraded available path and the incident continues to escalate by duration and affected-site count.
  • Suppression exception: Alarm suppression for NCS-SLA-2001 SLA Violation Detected requires operations manager approval and must not suppress NCS-SLA-2002 SLA Restored correlation.
